# TP-Link TL-WR886N V2.0 路由器固件安全评估报告

## 1. 评估概况

### 1.1 评估对象

本次评估以 TP-Link TL-WR886N 千兆版 V2.0 路由器固件为对象，主要通过固件静态分析检查固件结构、敏感信息、密钥材料、网络服务及第三方组件。

本次分析未对真实设备或在线管理界面进行攻击测试。

### 1.2 评估目的

1. 识别固件格式、系统架构和主要组件。
2. 检查是否存在硬编码口令、私钥、证书及敏感配置信息。
3. 分析网络服务、第三方组件和潜在攻击面。
4. 对发现的问题进行证据整理、风险判断和整改建议。
5. 形成可复现的固件分析记录。

## 3. 主要安全发现

以下保留第一轮评估报告中的九项发现。需要注意：风险等级属于静态分析阶段的初步评估，具体利用条件及影响范围仍需结合设备实际运行情况验证。

### VULN-01 硬编码出厂口令

**初步风险等级：高**

发现情况：

在 A200 主镜像中定位到 `fac_password`、`webPwd` 等相关字符串，并发现出厂口令候选值：

`WaQ7xbhc9TefbwK`

证据：

通过 strings 和 grep 搜索相关字符串及其上下文，发现 `webPwd`、`fac_password`、口令候选值及 `listen_http_lan`、`listen_http_wan` 等字符串相邻出现。

风险分析：

如果该口令被工厂模式、售后调试接口或其他认证逻辑使用，并且不同设备共享同一凭证，那么攻击者可能通过固件提取获得相关认证信息。

但目前仅凭静态字符串，尚不能完全证明该字段的实际认证逻辑、适用入口及所有设备是否共用。

分类参考：CWE-798（硬编码凭据）。

整改建议：

- 移除固件中通用的固定出厂凭证。
- 首次启动时生成每台设备独立的随机凭证。
- 工厂维护入口应采用独立认证机制。
- 对出厂凭证进行安全生命周期管理。

### VULN-02 硬编码 512-bit RSA 私钥

**初步风险等级：高**

发现情况：

在提取文件 C4500 中发现完整 PEM 格式 RSA 私钥。

第二轮通过 OpenSSL 和 Python cryptography 进行验证，成功解析出 RSA 私钥，密钥长度为 512 bit。

证据：

- 文件：C4500
- PEM 解析：成功
- RSA 密钥长度：512 bit
- 公钥指纹：由扫描器计算并保存

风险分析：

512-bit RSA 密钥长度明显不足，不符合现代安全使用要求。

如果该私钥被设备实际用于 TLS、签名或其他身份认证功能，可能导致相关密码学保护失效。

目前尚未通过运行时分析确认该密钥的具体用途、部署范围以及是否被所有同型号设备共用。

整改建议：

- 移除固件中嵌入的通用私钥。
- 每台设备使用独立生成的密钥对。
- 使用符合现代安全要求的密钥长度和算法。
- 对已经暴露的密钥进行轮换。

### VULN-03 HTTP 管理服务监听 WAN

**初步风险等级：高**

发现情况：

在 A200 中发现 `listen_http_wan` 等管理服务相关字符串。

证据：

通过 strings 和 grep 检索相关配置字段及其上下文。

风险分析：

如果管理服务实际绑定 WAN 接口，且缺少有效访问控制，可能增加管理界面暴露风险。

若与 VULN-01 中的硬编码认证凭证同时成立，可能形成远程访问风险链。

但静态字符串不能直接证明 WAN 侧服务当前处于启用状态，也不能证明外部攻击者可以成功登录。

整改建议：

- 默认关闭 WAN 侧管理。
- 管理服务仅允许受信任的 LAN 或管理网络访问。
- 对远程管理增加强认证和访问控制。
- 使用加密通信保护管理会话。

### VULN-04 Telnet 明文远程登录服务

**初步风险等级：中**

发现情况：

固件中出现 TELNET、TELNETD 等相关字符串。

证据：

通过 strings 和 grep 搜索相关服务标记。

风险分析：

Telnet 本身不提供传输加密，如果该服务实际启用，认证信息和交互内容可能以明文形式传输。

目前尚未通过运行时验证确认服务是否启用及监听范围。

整改建议：

- 默认禁用 Telnet。
- 使用 SSH 等加密管理协议替代。
- 限制管理服务的访问来源。

### VULN-05 UPnP 服务相关风险

**初步风险等级：中**

发现情况：

在模块清单和固件字符串中发现 UPnP、upnpd 等相关信息。

证据：

提取文件 C3E43 中发现 upnpd 模块相关记录，同时发现 UPnP 协议标识。

风险分析：

如果 UPnP 服务实际启用且访问控制不当，可能增加内网设备暴露和端口映射风险。

仅发现模块及协议标记，不代表已经验证出具体 UPnP 漏洞。

整改建议：

- 默认关闭不必要的 UPnP 服务。
- 限制 UPnP 的访问范围。
- 检查端口映射和授权机制。

### VULN-06 心跳 URL 中包含密码参数

**初步风险等级：中**

发现情况：

在固件字符串中发现类似以下格式的心跳请求模板：

`TYPE=HEARTBEAT&USER_NAME=%s&PASSWORD=%s&IP=...`

证据：

通过 strings 搜索 HEARTBEAT、USER_NAME、PASSWORD 等字符串。

风险分析：

如果实际请求将密码直接拼接到 URL 中，可能导致敏感信息被代理日志、服务器日志或其他记录机制保存。

目前尚未通过运行时抓包确认该模板的实际请求方式。

整改建议：

- 避免在 URL 中传输密码。
- 使用 HTTPS。
- 优先采用安全的认证令牌机制。
- 避免在日志中记录敏感认证信息。

### VULN-07 CyaSSL / wolfSSL 相关组件风险

**初步风险等级：中**

发现情况：

在固件中发现 `hello cyassl!` 等字符串，说明固件中存在 CyaSSL 相关实现或引用线索。

风险分析：

CyaSSL 是 wolfSSL 的前身。由于当前尚未确认精确组件版本及实际编译配置，因此不能仅凭该字符串直接认定某个 CVE 一定适用。

第一轮曾对相关历史漏洞进行过初步检索，后续需要结合精确版本、受影响配置和调用路径进一步核实。

整改建议：

- 确认实际组件版本。
- 核对对应版本的公开安全公告。
- 检查受影响功能是否被编译和调用。
- 对适用漏洞进行针对性修复或升级。

### VULN-08 jQuery 1.10.1 组件风险

**初步风险等级：中**

发现情况：

在固件 Web 资源中识别到 jQuery 1.10.1 相关文件和版本字符串。

证据：

- 文件：12EDDB
- 发现版本字符串：jquery 1.10.1
- 相关 Web 资源路径：web-static/lib/jquery-1.10.1.js

风险分析：

该版本较旧，存在需要进一步核查的历史安全问题。

但组件存在不等于漏洞一定可以被利用，还需要检查具体漏洞影响的 API、使用方式及攻击入口。

整改建议：

- 升级至仍受支持的版本。
- 检查页面对相关危险 API 的调用。
- 对 Web 管理界面进行针对性安全测试。

### VULN-09 内部构建路径和环境信息泄露

**初步风险等级：低**

发现情况：

在固件中发现厂商内部构建路径、芯片及板级信息。

证据：

例如：

`D:\jenkins\workspace\soho6_dragonfly_cloud_router_master_git\basicRouter\wireless\qca956x\os\vxWorks\wbuf_private.h`

风险分析：

固件残留的内部路径可能暴露开发环境、代码目录和硬件平台信息，为攻击者提供进一步分析线索。

整改建议：

- 发布前清理调试信息。
- 避免在正式固件中保留不必要的构建路径。
- 对日志和调试字符串进行发布前审查。

## 5. 第二轮复核补充

第二轮重点复核了 RSA 私钥、X.509 证书及扫描器识别结果。

| 文件 | 复核结果 | 说明 |
|---|---|---|
| A200 | PEM 私钥标记解析失败 | 标记之间没有实际密钥内容 |
| C4500 | RSA 私钥解析成功 | 512 bit |
| C3240 | X.509 证书解析成功 | VeriSign 根证书，RSA 2048 bit |
| C46C3 | X.509 证书解析成功 | TP-Link/SDMP 证书，RSA 512 bit，已过期 |

补充说明：

- C3240 的证书有效期为 2006-11-08 至 2036-07-16，签名算法为 SHA-1。
- C46C3 的证书有效期为 2014-05-08 至 2017-02-01，签名算法为 SHA-1。
- C46C3 证书的过期状态不代表设备一定拒绝或接受该证书。
- C46C3 证书包含 512-bit RSA 公钥，但它与 C4500 私钥是否匹配，尚未通过公钥指纹对比确认。
- A200 中的空证书标记不能计为有效证书。

## 6. 整体风险与整改建议

优先处理硬编码凭据和弱密钥问题，随后检查管理服务暴露、远程登录方式及第三方组件。

整改顺序：

1. 移除硬编码出厂凭证和固件内嵌通用私钥。
2. 关闭不必要的 WAN 管理、Telnet 和 UPnP 服务。
3. 检查心跳请求及认证数据传输方式。
4. 核实 CyaSSL 和 jQuery 的具体版本及适用漏洞。
5. 清理内部构建路径和调试信息。

## 7. 评估局限性

本次项目以固件静态分析为主，存在以下限制：

- 未对真实路由器进行在线渗透测试。
- 未确认所有发现对应功能在运行时是否启用。
- 部分组件的精确版本尚未确认。
- 部分 CVE 仍需核对适用版本和调用条件。
- 未完成全部密钥用途和证书部署关系验证。
- 未建立独立测试集，无法给出扫描器的误报率和漏报率。

因此，本报告中的发现应根据证据区分已验证事实、候选风险和待验证问题。

通过对 TP-Link TL-WR886N V2.0 固件的两轮分析，我完成了固件结构识别、文件提取、敏感信息审计、RSA 私钥和 X.509 证书验证，以及初步风险评估。

第二轮分析中，我对第一轮部分结论进行了复核，区分了真正可解析的密钥与仅存在格式标记的候选内容，并将人工检索过程逐步整理为 Python 自动化扫描工具。
