# OpenHarmony 6.1 智能手持终端 BSP 适配

这是我参加的一个校企合作项目。企业提供目标设备、基线工程、Android BSP 和屏幕/触摸参考补丁，我们在学校完成适配和调试。我主要负责系统构建链路以及 LCD、触摸这一部分，目标是让设备能够运行 OpenHarmony，并完成基本的人机交互。

这份仓库记录我的实际操作和复盘，不包含完整系统源码。

## 项目环境

| 项目              | 内容                                                         |
| ----------------- | ------------------------------------------------------------ |
| 系统基线          | OpenHarmony 6.1 企业基线                                     |
| 目标设备          | K608 智能手持终端                                            |
| 平台 / 构建产品名 | UNISOC UIS7885 / `wukong100`                                 |
| 内核              | 目标工程 Linux 5.15；参考 Android BSP 中包含 Linux 5.4 相关内容 |
| 显示 / 触摸       | HX8394F / CHSC5xxx                                           |
| 本地环境          | Windows 主机、VMware Ubuntu 虚拟机                           |
| 主要工具          | Git、Shell、厂商构建脚本、PAC 打包与下载工具、dtc、hdc       |

这里的平台名和路径沿用项目工程命名。设备树中还出现 `ums9620` 等名称，不把它们额外推断为其他硬件型号。

## 我负责的工作

- 搭建编译环境，编译 `wukong100` 基线，检查系统镜像并完成 PAC 打包、烧录验证。
- 参考企业提供的 BSP 和补丁，集成 HX8394F 屏幕及 CHSC5xxx 触摸相关代码和配置。
- 排查屏幕 ID 映射、LK 与内核显示配置不一致、I2C3 设备树时钟配置冲突等问题。
- 核对正式源码、构建副本、镜像目录和最终刷机包，处理修改未进入实际构建产物的问题。

适配基于企业提供的 BSP 与参考补丁展开，我负责目标工程的集成、配置修改、构建和排障；部分实机测试由队友配合完成。

## 已完成的结果

2026 年 8 月 15 日的调试记录中，我确认设备成功进入 OpenHarmony 界面。结合后续复盘，已完成屏幕显示和基本触摸操作验证。

当前验证范围为系统启动、屏幕显示和基本触摸操作。连续运行、反复重启、休眠唤醒与触摸精度属于后续专项测试范围。

详细过程见 [编译、屏幕与触摸适配复盘](Display-Driver-Porting.md)。

## 我从这个项目中学到的事

最开始，我把“编译成功”“打包成功”“烧录成功”和“设备能正常使用”看得太接近了。实际调试之后才发现，每一步都需要单独验证。

同样，源码改对也不代表设备运行的就是这份代码。真正需要核对的是：改动有没有进入构建副本、新产物有没有更新、打包脚本有没有使用新产物、刷机时有没有选到这一次的包。这是我这次项目最深的体会。
